# C8.6 - Identifier-Aware Abstention Calibration

## Motivation

C8.5 completed its runtime inference and produced numeric cross-encoder scores, but no scalar or sampled joint threshold passed the calibration gates. Reviewing only its 60 calibration cases showed seven false-positive queries at the recall-preserving cross-encoder cutoff: six were nonexistent near-identifier lookups and one was a hard semantic negative.

An offline, calibration-only policy simulation used a generic structured-code detector and exact literal matching. It removed the six near-identifier false positives while preserving all 30 positives; the one hard-semantic false positive remained. This meets C8.5's empirical calibration gate, but it is not a workflow result and is not evidence about any holdout.

## C8.6 policy under test

- Detect a structured identifier from query text, requiring both letters and digits separated by punctuation.
- If an identifier is present, keep only candidates containing every queried identifier exactly (case-insensitive; punctuation and digits remain significant).
- Apply the calibrated cross-encoder cutoff to the surviving candidates. Natural-language queries without structured identifiers use the same calibrated cutoff without the exact-code condition.
- This is an evaluator policy only. It does not change retrieval order, RRF, ID fusion, or production runtime behavior.

## Fresh fixture and gates

C8.6 generates new records, codes, topics, and queries; it does not re-key C8.4/C8.5. Calibration and holdout are split-isolated:

- Each split: 50 answerable queries and 100 no-answer queries.
- Each split has 20 exact-identifier positives and 30 near-identifier negatives across five identifier formats.
- Remaining negatives cover hard semantic questions that reuse the entity/context but ask for a missing owner or recovery code, hard lexical decoys, scope-confusion, out-of-domain, and missing-attribute cases.
- The existing gates remain unchanged: recall >= 90%, exact-ID recall = 100%, no-answer FPR <= 5%, and zero namespace/forbidden-marker leaks.

The manual C8.6 workflow pins the already verified small cross-encoder runtime image. It queries holdout only if calibration selects a policy that passes every gate; otherwise it exits fail-closed. Each split has 100 negatives so empirical FPR resolution is 1 percentage point. This improves precision over the 30-negative C8.5 calibration, but it is still an empirical gate, not a finite-sample 95% guarantee.

No image is rebuilt, no production setting changes, and no holdout query runs automatically on push or schedule.
