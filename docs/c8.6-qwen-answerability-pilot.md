# C8.6 Qwen answerability pilot

The C8.6 pilot uses OpenRouter's hosted `qwen/qwen3-reranker-0.6b` rerank API
from a manual local invocation. The script generates its fixture internally from the
checked-in `c86_fixture_generator.py`; it accepts no caller-supplied fixture path.
Each API request checks the exact query and every candidate against allowlists built
from the generated calibration split. Temporary fixtures use `RUNNER_TEMP`, otherwise
`C86_SCRATCH_DIR`, then `/opt/data/cache/scratch`, and are removed when the run exits.
Nyawa/BGE retrieval remains in a disposable local container, and the CLI inserts and
queries calibration-split data only. Only those
synthetic queries and top candidate texts are sent to OpenRouter. `OPENROUTER_API_KEY`
must be supplied through the process environment and is never written to the report or
logs. No Qwen weights or Torch runtime are loaded locally.

The API returns per-document `relevance_score` values, not the yes/no logit margin
from the former local Transformers implementation. Therefore, do not reuse old
thresholds or claim equivalence: the 150 calibration queries must select a new
Qwen-only score cutoff with the existing exact structured-identifier guard. The
C8.6 recall, exact-ID recall, false-positive, namespace-leak, forbidden-marker,
numeric-score, raw-modality, and cross-encoder evidence gates remain unchanged.

The CLI has no holdout mode: it runs calibration-only, and the evaluator may inspect
holdout only after a feasible calibration policy exists through a separate explicitly
approved action. If calibration is infeasible or an API response is incomplete/invalid,
the run fails closed.

The GitHub Qwen calibration jobs were removed because the full CPU inference could
not fit the PR job budget. Fast static validation and offline mocked API tests remain
in CI; actual reranking is manual/local and requires network access plus OpenRouter
credits. Example:

```bash
export OPENROUTER_API_KEY="<set securely; do not paste into shell history>"
python3 scripts/c86_qwen_answerability.py --mode calibration-only
```

This does not use production records, alter production runtime/configuration, or call
Hermes. The disposable Nyawa container is still cleaned up on success or failure.
