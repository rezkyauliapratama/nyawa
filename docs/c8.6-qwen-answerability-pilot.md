# C8.6 Qwen3 answerability pilot

This PR-only pilot scores the C8.6 retrieval candidates with the local
`Qwen/Qwen3-Reranker-0.6B` model at immutable revision
`e61197ed45024b0ed8a2d74b80b4d909f1255473`. It compares the next-token yes/no
logits under an answerability-specific instruction and records `yes - no` as
the candidate score. The model is downloaded to the GitHub-hosted runner cache;
no weights are stored in this repository or added to a runtime image. The
CI-only Python pins live in `scripts/requirements-c86-qwen-ci.txt`.

Calibration uses only the 150 C8.6 calibration queries. Policy selection is
restricted to a Qwen score cutoff combined with the existing exact
structured-identifier guard; no unguarded Qwen score, legacy cross-encoder, or
retrieval signal can make the Qwen pilot feasible. The unchanged C8.6 recall, exact-ID recall,
false-positive, namespace-leak, forbidden-marker, numeric score, raw modality,
and cross-encoder evidence gates remain in force. Qwen candidate scores must
also be numeric. Only after a Qwen-only calibration policy passes all gates
are the 82 holdout records inserted and the 150 holdout queries evaluated once.
If calibration is infeasible, holdout records are neither inserted nor queried.

The workflow runs on pull requests touching the pilot inputs. It uses local
Transformers inference only, makes no provider/API calls, and does not change
production images or configuration. This pilot has not been executed on the
GitHub runner from this worktree; local verification uses fake scorers and
static checks only.
