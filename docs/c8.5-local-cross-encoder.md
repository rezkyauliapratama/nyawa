# C8.5 - Local Cross-Encoder Confidence Experiment

## Motivation

C8.4 raw retrieval achieved 100% recall on calibration, but no-answer FPR was 100%. An exact calibration-only sweep across 14,000 `VectorDistance`/`FTS5RankScore` pairs found no feasible policy; the best zero-FPR recall was 46.7%. A separate grouped five-fold logistic experiment over existing retrieval features also found no threshold meeting the gates. The C8.4 holdout was never queried.

C8.5 adds an independent query-passage interaction score from a local multilingual cross-encoder. The score is telemetry for abstention calibration only: it does not alter RRF or final candidate ordering.

- Pinned Hub revision: `23139fec6f1f448cdf89a5ac2d2c6bf5e8c7b398`.
- Quantized ONNX SHA-256: `f913154682468bfe92d6a7e02ed4e994e548c112fddc74452b573b17c949046e`.
- Tokenizer SHA-256: `7925f638b5444897efe3b4608eed56c1652f0ed39c2662c8302de1bc264c6088`.
- The image includes this asset only when the publish workflow is explicitly dispatched with `include_reranker=true`. The image build performs a local inference smoke test.
- Runtime activation is opt-in (`NYAWA_ENABLE_CROSS_ENCODER=1`). If enabled but the model fails to load or score, recall fails closed. Scores are attached as `CrossEncoderScore`; they never affect ranking.
- Inference uses the runtime's existing hash-pinned ONNX Runtime, Tokenizers, and NumPy packages; no provider/API call or model download occurs at runtime.

## Evaluation protocol

C8.5 re-keys the C8.4 synthetic corpus under a new schema and requires numeric cross-encoder scores. Its calibration split is used to sweep score and margin thresholds, optionally conjoined with existing retrieval evidence. The still-unqueried C8.4 holdout is evaluated once only if a policy passes calibration gates. If calibration has no feasible policy, stop without querying holdout. The C8.3 holdout remains retired.

No production database/HNSW, provider/Hermes, deployment, VM/WS-1, or resource increase is in scope.
